In the **Colosseum O-RAN COMMAG Dataset** (`wineslab/colosseum-oran-commag-dataset`), cellular network telemetry is exported as CSV files generated by srsLTE software running on Distributed Units (DUs).

The full telemetry metrics list contains **36 parameters** (columns). Below is the complete list of available parameters categorized by their network function, along with the role and significance of each.

---

### 1. Context & Identifiers

* **`Timestamp`**: Epoch time/timestamp indicating when the metric observation was logged by the DU.
* **`num_ues`**: Total number of active User Equipments (UEs) currently connected to the base station/cell.
* **`IMSI`**: International Mobile Subscriber Identity; a unique global identifier assigned to each cellular subscriber/device.
* **`RNTI`**: Radio Network Temporary Identifier; a temporary ID assigned to a UE by the eNodeB/gNodeB for active radio link communications.
* **`slice_id`**: Identifier for the network slice to which the UE or traffic stream belongs (e.g., `0` for eMBB, `1` for MTC, `2` for URLLC).

---

### 2. Configuration & Scheduling Control

* **`slicing_enabled`**: Binary flag (`0` or `1`) indicating whether O-RAN network slicing control is currently enabled.
* **`slice_prb`**: Number of Physical Resource Blocks (PRBs) or Resource Block Groups (RBGs) allocated to the slice.
* **`power_multiplier`**: Scale factor applied to transmit power management for radio control.
* **`scheduling_policy`**: Active MAC-layer scheduling algorithm being applied to the slice (`0`: Round-Robin [RR], `1`: Waterfilling [WF], `2`: Proportionally Fair [PF]).

---

### 3. Downlink Metrics (RAN to UE)

* **`dl_mcs`**: Modulation and Coding Scheme used for Downlink transmissions. Determines link efficiency and spectral throughput based on channel quality.
* **`dl_n_samples`**: Number of samples or data points recorded for Downlink measurements during the reporting interval.
* **`dl_buffer [bytes]`**: Downlink buffer size in bytes awaiting transmission in the RLC/MAC queues. Higher values indicate queue congestion.
* **`tx_brate downlink [Mbps]`**: Downlink transmitted bit rate (throughput) achieved, measured in Megabits per second (Mbps).
* **`tx_pkts downlink`**: Total count of downlink packets transmitted during the monitoring window.
* **`tx_errors downlink (%)`**: Percentage of transmitted downlink packets that failed or required retransmissions (BLER/Packet Error Rate).
* **`dl_cqi`**: Channel Quality Indicator (0–15 scale); reported by the UE to inform the base station of the Downlink radio signal quality.
* **`dl_pmi`**: Precoding Matrix Indicator; used in MIMO channel feedback to optimize spatial beamsteering/precoding.
* **`dl_ri`**: Rank Indicator; represents the number of independent spatial transmission layers (streams) the MIMO channel can support.

---

### 4. Uplink Metrics (UE to RAN)

* **`ul_mcs`**: Modulation and Coding Scheme assigned for Uplink transmissions.
* **`ul_n_samples`**: Number of Uplink data samples recorded during the logging period.
* **`ul_buffer [bytes]`**: Buffer backlog awaiting transmission on the Uplink side in bytes.
* **`rx_brate uplink [Mbps]`**: Uplink received bit rate (throughput) at the base station in Mbps.
* **`rx_pkts uplink`**: Total count of uplink packets successfully received by the base station.
* **`rx_errors uplink (%)`**: Percentage of uplink packets received with errors.
* **`ul_rssi`**: Received Signal Strength Indicator; total received power (signal + interference + noise) in dBm on the Uplink.
* **`ul_sinr`**: Signal-to-Interference-plus-Noise Ratio; measures Uplink channel quality and signal clarity in dB.
* **`phr`**: Power Headroom Report; indicates the remaining transmit power available at the UE before reaching its maximum limits.
* **`ul_n`**: Number of uplink transmission noise/channel estimate samples.
* **`ul_turbo_iters`**: Average number of turbo decoding iterations required by the receiver to decode uplink physical channel data.

---

### 5. Resource Demand & Allocation (PRB Dynamics)

* **`sum_requested_prbs`**: Cumulative number of Physical Resource Blocks requested by UEs to fulfill their traffic demand during the epoch.
* **`sum_granted_prbs`**: Cumulative number of Physical Resource Blocks actually granted by the MAC scheduler.
* **`ratio_granted_req`** *(Derived metric created in testing/agent scripts)*: $\frac{\text{sum\_granted\_prbs}}{\text{sum\_requested\_prbs}}$. Used specifically as the reward function metric for URLLC slices—higher ratios indicate lower scheduling latency.

---

### 6. Reserved/Unused Padding Columns

* **`empty_1`**, **`empty_2`**, **`empty_3`**, **`empty_4`**, **`empty_5`**: Reserved or empty placeholder columns in the raw srsLTE CSV logging output format.
